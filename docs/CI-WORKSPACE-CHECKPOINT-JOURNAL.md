# 可恢复的流式回复日志

代码 `01a6124` 将已有对话的流式消息检查点保存在小型日志中。每次成功提交仍先保存独立的上一版完整备份，再原子写入并同步日志，最后发布内存状态。日志绑定主文件的 SHA-256、文件标识及纳秒修改时间；损坏、越界、重复索引和错误归属被拒绝，临时对话不落盘。正常保存与退出会将状态恢复为原有规范 JSON 文件。

完整 711 项／69 个测试文件、类型检查和构建通过。实际启动检查覆盖工作区、凭据及日志损坏三种情况，确认准确故障阶段、非阻塞退出且不记录私有输入。测试还覆盖排队读取、保存失败后的重试、清理失败后旧日志不能重放以及读取期间文件增长。

同一份 84,064,332 字节、297 条对话的本机样本中，四次实际检查点更新加最终完整文件写入由约 8.02 秒降至 4.96 秒；其中日志更新约 4.11 秒，最终写入约 0.85 秒。两次运行的输入、最终主文件和上一版备份逐字节一致。这是单次本机测量，不代表所有环境。

旧现场副本的六项模型比较断言曾通过，但该次运行最后的正常窗口关闭失败。下一次运行在第四项后失败：续聊部分回复未满足原有 10 秒／100 ms 条件。完整桌面、当前分发包、安装版及远端流水线均未通过当前应用体的验收，不使用历史记录替代。实际来源、日志哈希及观测见 `verification/workspace-checkpoint-journal-component-result.json`。

## 草稿、续聊与活动对话

代码 `a39565f` 将结构不变的草稿、活动对话与已有对话续聊启动纳入日志事务。新增、删除、重排对话或更改其他工作区字段时，回退到原有完整文件事务。日志中的草稿和活动归属也必须与主文件匹配；消息检查点继续保留草稿元数据。仅改变临时数据时不会触发普通数据落盘。

前一版 `f1734e1` 的六项模型比较断言全部通过，但正常关闭仍失败。实际关闭观测显示六次活动对话保存已经进入调用，其中三次在第 4 秒的观测点尚未结束。当前版本合并事务尚未开始时的选择，立即占据原有保存队列的位置，在最新选择落盘后才返回成功；无效归属与写入失败仍分别返回错误。普通和临时选择保留独立边界，使重启可以恢复此前最后一个普通对话。

完整 728 项／69 个文件、类型检查和构建通过。相同旧现场副本的六项原生比较检查及正常关闭通过，部分回复约 8.43 秒满足原有 10 秒／100 ms 条件。三项实际启动故障检查也通过。九份截图独立保存于 `verification/checkpoint-journal-native/`；当前应用体与前一版关闭失败证据见 `verification/activation-coalescing-component-result.json` 和 `verification/conversation-journal-close-failure-result.json`。此结果是聚焦组件验收，完整桌面、分发与远端结果仍需另行通过。
