# 回复版本

“重新生成”会先在同一次本地保存中保留旧回复及其完整上下文，再开始新回复。当前对话沿用原有 ID，旧版本存入“已归档”；重新生成保留原用户消息的 ID、时间、手动编辑标记和附件，不重复添加用户回合。保存失败不会覆盖旧版本，也不会开始模型请求。切换模型后重新生成，可比较同一问题的不同模型结果，各版本保留实际生成模型和用量记录。

有多个版本的回复下方会显示“版本”。点击可选择并预览完整纯文本，包含已完成、失败或停止的结果；预览和取消不会请求模型。“打开此版本”切换到该回复所属的对话路径，之后发送使用所选版本的上下文。每条路径各自保存后续对话，切换回来不会丢掉其中一条路径的后续消息。同一回复在普通分支中复制的前缀只显示一次；当前路径优先，否则打开最近更新的对应路径。

重新生成前会等待现有草稿保存，旧版本复制当时已保存的草稿与附件、模型及其他选择；之后各版本的草稿独立保存。恢复所选版本时沿用已有选择过滤、草稿存储和正常退出保护。归档版本可以继续聊天，也可以单独删除；删除当前对话仅删除该路径和它的草稿，其他路径仍保留，可在“已归档”管理。

旧回复保留原文、时间、附件、工具执行证据、知识来源和完整模型请求／用量记录。查看旧版本不会重新执行工具。失败或停止的新回复仍是一个可见版本，之前成功的回复保持可用。完整 JSON／gzip 备份保存版本关系、各条路径及草稿，恢复保留版本 ID 和顺序。旧工作台没有版本字段时照常读取，之后的重新生成会保存当时已有的回复。

手动编辑助手回复并选择“仅保存”也会加入回复版本，选择器显示手动编辑标记，原生成证据继续保留。重新生成时，被替换回复尚未保存的编辑草稿随旧回复转移到归档；原本有效的历史校验随归档更新，已有冲突继续提示。详情见 [MESSAGE-EDITS.md](MESSAGE-EDITS.md)。

版本与对话沿用 10000 条对话上限，每个回复组最多 10000 个版本编号；复制草稿仍受 100 个所有者和 32 MB UTF-8 总量限制。达到限额会拒绝重新生成，不会自动丢弃旧版本。不同路径同时重新生成时，版本编号在串行保存内分配，避免重复编号。

本功能的 6 项原生检查已在源码和实际打包 EXE 的完整回归中分别通过，覆盖实际界面重新生成与纯文本预览、准确的模型 HTTP 上下文、各自草稿、保存失败回滚、失败和停止、正常退出／重启及完整 gzip 恢复。4 张新增浅色、深色、最小窗口和失败状态截图已检查，最小窗口无横向溢出且操作按钮可见。完整验收记录见 [DELIVERY.md](DELIVERY.md)。

实现参考了外部 Chatbox 的持久回复分叉、Cherry Studio 的回复兄弟组与实际模型记录、OpenCode 的独立上下文分支，使用本项目现有会话、归档与原子保存流程独立实现，没有导入竞品代码。单元检查覆盖格式、分组与前缀去重、并发编号、准确上下文、真实落盘／重启／备份、保留失败和停止结果、限额及保存失败。同组版本也可通过 [分支导航](CONVERSATION-BRANCHES.md) 以层级关系浏览和切换。最大界面规模性能、完整无障碍和其他平台仍需单独验证。
