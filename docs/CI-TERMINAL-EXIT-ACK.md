# 终端退出回调与应用关闭

2026-10-26：完整 144 文件／1,696 项单元测试、类型检查和构建通过，语句覆盖率 97.10%。最终源码原生专项通过 7 项；同一夹具运行旧基线包时，前六项通过，第七项因宿主提前正常退出而失去调试连接，未进入保留窗口流程。旧包失败是预期的回归对照，不是对历史原生异常的复现。完整源码和新分发验收另行记录。

终止 shell 的操作返回，不代表 node-pty 的退出回调已经送达。此前 `TerminalSessions.close()` 在开始终止前移除了退出监听器，只等待 kill 操作返回，因此应用 shutdown 可能在原生退出回调之前完成。新增回归测试在旧实现上确认了这个提前返回。

关闭现在同时等待终止操作和 PTY 的退出事件，再释放监听器和会话名额。等待期间不向已关闭面板发送输出。5 秒内未收到事件会报告失败，并保留原会话及监听器，允许继续接收迟到退出并重试；失败的进程仍占用原来的 16 个会话名额。应用关闭失败会重置退出状态，使再次退出继续执行清理。

验证包括迟到退出、并发关闭／shutdown、超时后的会话与输出保留、16 个未完成进程的名额约束、终止失败后的重试，以及真实 Windows PowerShell 和子进程的自然退出、显式关闭、应用退出。新增原生夹具只在真实 native 回调到达后暂存应用监听器，检查应用在超时时保留窗口，释放回调后再次退出成功。原 10 秒正常退出门槛保持不变。

上游 [node-pty #951](https://github.com/microsoft/node-pty/issues/951) 描述了环境销毁期间退出回调可能触发 `0xc0000409` 的原生异常，[#954](https://github.com/microsoft/node-pty/pull/954) 是尚未合并的原生编译保护提案。本次修复使用现有公开退出事件完成应用侧清理，不修改或重编译原生依赖。这里修复的是已复现的应用清理时序缺陷；没有原始崩溃调用栈证明该缺陷就是历史异常的唯一根因，也不能把专项通过等同于新分发的完整验收。
