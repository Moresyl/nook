# Native runtime verification

The project pins node-pty 1.1.0, xterm 6.0.0, its fit addon 0.11.0, Monaco 0.57.0 and the React editor adapter 4.7.0. All editor language workers are built into the application; no editor CDN is used. Production renderer assets use the restricted `qiyao://app` origin so packaged workers have a secure, consistent origin.

node-pty uses Node-API and ships Windows x64 prebuilt binaries. Packaging keeps the complete module outside ASAR because native modules, helper executables and DLLs need filesystem paths. `npmRebuild` is disabled to reuse those fixed upstream binaries; their real PTY paths have passed both source and packaged Electron 44.5.1 verification. Rebuilding locally would additionally require the vendor's Spectre-mitigated Visual C++ libraries. No upstream build-security flags were removed.

Before changing Electron or the native terminal dependency, rerun the packaged desktop checks. They execute real PowerShell input, ANSI rendering, resize, renderer reload/replay, natural exit, child-process termination and application shutdown. Mocked service tests cover session ownership, geometry, input bounds, limits, errors and bounded output snapshots.

Git operations require system Git and preserve its configured identity and hooks. The desktop tests use an isolated fixture repository and verify that committing a selected staged file preserves unrelated worktree changes.

Local JSON saves create an exclusive sibling staging file with mode 0600, write UTF-8 data, flush and close it before replacing the saved file. On Windows, replacement errors EPERM/EACCES/EBUSY receive at most six short delays totaling 1.05 seconds. Other errors fail immediately. Failure retains the old file, reports a generic storage error and attempts to remove the staging file without masking the original error. This applies to workspace, backup and encrypted credential JSON; project file writes retain their separate revision/approval checks. File flushing does not establish survival of every power or filesystem failure, and abrupt process termination can leave staging files.

The focused persistence check opens workspace.json in a real separate PowerShell process with delete-sharing denied for 600 ms. It requires an actual rejected replacement and a successful preference save after release. It then combines twelve live streaming/checkpoint/draft/stop cycles with continuous disk JSON reads, checks every final stopped response and requires no corrupt read or remaining staging file. The Windows sharing failures and concurrent reads are real operating-system operations; provider data remains an isolated local fixture. Result files record source/packaged runs separately.

Windows artifacts include installer, portable and unpacked applications with Nook product branding; the current candidate is unsigned. Each candidate requires matching executable/archive hashes, original dependency and asset licenses, and native runtime results. See [current release status](RELEASE.md) for the exact candidate, passing checks and unresolved failures; the earlier [179-check distribution record](../verification/recovery-distribution-result.json) is historical evidence, not acceptance of newer builds. Main and isolated plugin interfaces load the OFL Inter font. Update behavior, physical wizard/picker interaction, broader delivery gates and native processes on other platforms remain separate work.
