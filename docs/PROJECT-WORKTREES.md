# 项目工作树

在独立文件夹中使用另一个 Git 分支，同时保留原项目的分支、暂存区、文件改动与编辑草稿。适合并行处理功能、修复或审阅；创建后的文件来自提交版本，原项目未提交的改动不会复制过去。

## 创建与打开

1. 打开「项目 → 查看改动」，点击分支按钮旁的「管理项目工作树」。
2. 选择新建分支，按需选择起始本地分支；也可以使用未被占用的已有本地分支。
3. 确认或修改建议的绝对文件夹路径。目标文件夹必须尚不存在，并且位于现有工作树之外；默认目录在首次创建时准备，其他父目录必须已存在。
4. 创建后核对实际分支和路径，点击「添加为项目」，再点击「打开项目」。新项目可独立编辑、使用终端和创建聊天；项目指令初始为空，可在项目设置中填写。

创建与登记分别执行。关闭创建结果不会删除工作树；展开「已有工作树」可查看并重新登记。已经登记的工作树显示「打开项目」，不会再次添加。项目登记失败时保留创建结果、名称和同一项目 ID，重试「添加为项目」即可，无需重新创建。

## 默认创建位置

在「设置 → 工作树」填写已有目录的绝对路径，或点击文件夹按钮通过系统窗口选择，再点击「保存工作树设置」。选择成功只更新输入，取消保留原输入，选择失败可重试；选择期间设置分类、输入和关闭操作锁定。之后打开创建表单时，会建议该目录下新的 `nook-xxxxxxxx` 文件夹；仍可修改目标路径。

留空时使用当前资料目录下的 `worktrees` 默认目录，设置输入的占位文字显示该路径。读取路径、打开设置和打开创建表单都不创建文件夹；实际 Git 请求通过分支、起始提交与目标路径检查后，才准备这一层默认目录。自行指定的根目录与其他父目录仍须已存在；应用不会创建任意父目录，也不把推导路径写入配置。

默认位置若已被文件或目录联接占用，创建会保留现场并提示在设置中选择已有目录。准备失败保留配置、输入和原仓库，修复权限或修改设置后可重试。设置只影响未来创建，不移动现有工作树、不获取远程分支、不自动删除文件。工作台备份包含根目录配置；Git 工作树文件留在本地，不会打包进工作台备份。

保存期间锁定设置分类、输入与关闭操作。失败后保留原设置和输入，显示中文提示，可直接重试。根目录设置随工作台备份和恢复保存。

## 失败与保留

- 拒绝已有目标文件夹，包括空文件夹和失效的目录联接；不覆盖文件、不强制重置分支。
- 拒绝已被其他工作树使用的分支。外部 Git 操作可能让列表过期，刷新后再操作。
- 起始提交在创建前固定。创建过程中其他进程移动起始分支，不会改变已经选定的新工作树提交。
- Git 钩子可能在目录和分支已经创建后报错，或者改变实际分支。界面会读取实际状态并提示检查，不把已完成的创建当作可以无条件重复的失败。
- 未完成的目标目录与文件会保留。刷新已有工作树、检查文件夹和 Git 状态后再决定如何处理；应用不会自动递归清理部分结果。

新建工作树不会切换原项目分支，也不会关闭原项目的 HTML 预览。移除项目登记沿用现有项目行为，保留本地文件，并不执行 `git worktree remove`。
