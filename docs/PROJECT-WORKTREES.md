# 项目工作树

在独立文件夹中使用另一个 Git 分支，同时保留原项目的分支、暂存区、文件改动与编辑草稿。适合并行处理功能、修复或审阅；创建后的文件来自提交版本，原项目未提交的改动不会复制过去。

## 创建与打开

1. 打开「项目 → 查看改动」，点击分支按钮旁的「管理项目工作树」。
2. 选择新建分支，按需选择起始本地分支；也可以使用未被占用的已有本地分支。
3. 确认或修改建议的绝对文件夹路径。目标文件夹必须尚不存在，并且位于现有工作树之外；默认目录在首次创建时准备，其他父目录必须已存在。
4. 创建后核对实际分支和路径，点击「添加为项目」，再点击「打开项目」。新项目可独立编辑、使用终端和创建聊天；项目指令初始为空，可在项目设置中填写。

创建与登记分别执行。关闭创建结果不会删除工作树；展开「已有工作树」可查看并重新登记。已经登记的工作树显示「打开项目」，不会再次添加。项目登记失败时保留创建结果、名称和同一项目 ID，重试「添加为项目」即可，无需重新创建。

## 本机创建记录

应用完成实际 Git 创建后，单独保存本机创建记录；普通列表浏览和「添加为项目」不会把已有外部工作树纳入管理。记录包含目录与 Git 归属的实际身份，位置被替换或记录异常时不取得管理权限；记录不进入可分享的工作台备份。

记录保存失败仍保留已创建的工作树和创建结果，并提示「工作树已创建，但创建记录未能保存。文件已保留，此工作树不会自动清理。」可以继续显式添加为项目，无需重新创建。只有核验通过的本机创建记录才提供快照与安全删除入口。

## 固定工作树

在「设置 → 工作树」找到本机创建的工作树，点击「固定工作树」或「取消固定工作树」。固定状态仅保存于本机创建记录，正常重启保留；共享工作台备份不包含创建记录或固定状态，恢复共享备份也不会回滚本机较新的固定状态。

主工作树和外部创建的工作树没有固定入口。创建记录未能核验时，显示保留文件说明并禁用固定；记录读取失败显示提示，刷新后重试。保存过程中锁定设置操作，失败保留旧状态和文件。项目来源变化或实际目录被移动、替换时拒绝旧入口，不能用相同路径采纳外部新建目录。

六组真实桌面专项与两主题三档缩放的实际键盘固定操作通过；写入失败重试、来源变更、记录损坏恢复、gzip 备份隔离和正常重启均有文件断言。固定目前管理本机元数据，尚不执行自动清理。[固定专项](../verification/worktree-pinning-notice-review-result.json)

## 保存与恢复快照

在「设置 → 工作树」找到经过核验的本机工作树，点击「保存工作树快照」。固定的工作树也可保存；主工作树、外部工作树与未核验记录没有保存入口。展开同一仓库的「已保存快照」，点击「恢复到新目录」，填写尚不存在、位于现有工作树之外的绝对路径；父目录必须已存在。

快照包含提交历史、暂存区以及普通工作区文件（含未跟踪和忽略文件）。恢复新建处于分离提交状态的工作树，保留原项目、分支、文件和草稿。私有快照仅保存在本机，工作台共享备份不包含这些文件；恢复共享备份不会回滚私有快照。

每份最多 4,096 个文件、单文件 16 MiB、文件总计 64 MiB；本机最多保存 100 份。链接、特殊文件、损坏资料和不支持的索引状态会拒绝处理，错误保留输入和现有快照。恢复中途失败可能留下新目录的部分结果：刷新 Git 列表并检查该目录，再选择另一个新目录重试；应用不会递归删除部分结果。退出会等待已接受的快照操作完成。

## 安全删除

在「设置 → 工作树」找到符合条件的本机工作树，点击「删除工作树」，核对路径后选择「保存快照并删除」。应用先在本机持久保存并重新读取快照，再调用 Git 删除工作树；源仓库和分支继续保留。可从「已保存快照」恢复到尚不存在的新目录。

主工作树、外部或身份变化的目录不可删除。固定、已登记为项目、关联固定聊天、运行中的回复／终端、编辑草稿、Git 锁定、已修改／暂存／未跟踪／忽略文件均会阻止删除。移除项目登记后，原关联聊天的固定状态仍受保护，正常重启也保留；需显式取消固定后再试。

快照保存失败不开始删除。删除完成但创建记录更新失败时显示明确提示，快照继续保留；Git 删除失败可能留下部分处理结果，应刷新列表并检查目录，必要时恢复到新目录。应用不会强制删除、删除分支或递归移除部分结果。操作期间禁止重复提交和关闭确认框；退出等待已接受的清理完成。应用内排他不能锁住外部文件进程。

## 自动清理

默认关闭。在「设置 → 工作树」保存 1～50 的「保留工作树数量」，再启用「自动清理旧工作树」。每次成功创建并保存本机记录后，按创建时间保留最新数量，尝试清理更早的合格空闲工作树；同样先保存快照，再删除。受保护的旧树会跳过，实际总数可能超过保留数量；界面显示实际删除、跳过和记录更新失败情况。

停用时选择「保留自动清理」取消，或「停用自动清理」确认。停用不删除已有工作树或快照。达到本机 100 份快照上限或快照无法保存时，不继续清理。

## 默认创建位置

在「设置 → 工作树」填写已有目录的绝对路径，或点击文件夹按钮通过系统窗口选择，再点击「保存工作树设置」。选择成功只更新输入，取消保留原输入，选择失败可重试；选择期间设置分类、输入和关闭操作锁定。之后打开创建表单时，会建议该目录下新的 `nook-xxxxxxxx` 文件夹；仍可修改目标路径。

留空时使用当前资料目录下的 `worktrees` 默认目录，设置输入的占位文字显示该路径。读取路径、打开设置和打开创建表单都不创建文件夹；实际 Git 请求通过分支、起始提交与目标路径检查后，才准备这一层默认目录。自行指定的根目录与其他父目录仍须已存在；应用不会创建任意父目录，也不把推导路径写入配置。

默认位置若已被文件或目录联接占用，创建会保留现场并提示在设置中选择已有目录。准备失败保留配置、输入和原仓库，修复权限或修改设置后可重试。设置只影响未来创建，不移动现有工作树、不获取远程分支、不自动删除文件。工作台备份包含根目录配置；Git 工作树文件留在本地，不会打包进工作台备份。

保存期间锁定设置分类、输入与关闭操作。失败后保留原设置和输入，显示中文提示，可直接重试。根目录设置随工作台备份和恢复保存。

## 创建前刷新上游

在「设置 → 工作树」开启「创建工作树前刷新上游」，之后创建工作树时会获取所选本地分支的远程上游。旧资料默认关闭；保存开关保留尚未提交的根目录输入，保存根目录也保留开关。设置随工作台备份、恢复和重启保存。

创建仍使用已经选定的本地提交。获取只更新对应的远程追踪引用，不合并或切换原项目分支，不改写文件和暂存区。分支没有远程上游时直接从本地创建；获取失败时也保留本地创建结果，显示提示，可检查仓库访问权限后再次创建。关闭开关不会执行获取。

## 失败与保留

列表加入后的完整源码首次回归在 283 项、40 次正常退出后失败。旧根目录测试误计列表内九个独立项目的错误；测试改为定位根目录直属错误，保留所有数据、忙碌和错误文本断言。重放原失败工作区后十组根目录专项、三次正常退出通过，最长 598ms；20 张原图逐张复核，七个根目录错误边界保留。后续聊天入口应用体已通过上述 316 项完整源码回归，分发仍待验收；原失败继续保留。[失败现场与专项重试](../verification/worktree-overview-root-retry-result.json) · [20 张原图范围](../verification/worktree-overview-root-originals-review-result.json)

- 拒绝已有目标文件夹，包括空文件夹和失效的目录联接；不覆盖文件、不强制重置分支。
- 拒绝已被其他工作树使用的分支。外部 Git 操作可能让列表过期，刷新后再操作。
- 起始提交在创建前固定。创建过程中其他进程移动起始分支，不会改变已经选定的新工作树提交。
- Git 钩子可能在目录和分支已经创建后报错，或者改变实际分支。界面会读取实际状态并提示检查，不把已完成的创建当作可以无条件重复的失败。
- 未完成的目标目录与文件会保留。刷新已有工作树、检查文件夹和 Git 状态后再决定如何处理；应用不会自动递归清理部分结果。

新建工作树不会切换原项目分支，也不会关闭原项目的 HTML 预览。移除项目登记沿用现有项目行为，保留本地文件，并不执行 `git worktree remove`。
