# 消息编辑与编辑草稿

用户消息的“编辑消息”和助手回复的“编辑回复”都提供“仅保存”。保存会更新当前消息的正文，保留后续消息、附件和当前聊天草稿，同时在同一次本地保存中将编辑前的完整对话存入“已归档”。保存沿用当前对话 ID，不请求模型；之后发送使用保存后的文本作为上下文。用户消息仍可选择“在新分支中发送”，沿用已有重发与审批流程。

仅保存的消息显示“已手动编辑”。助手回复的实际生成模型、请求用量、状态、错误、工具证据和知识来源保留为原生成记录；修改正文不会重新计算用量或执行工具。后续回复也保留原生成记录，完整的编辑前对话可在归档中查看。助手的手动修改加入回复版本，选择器标明“手动编辑”，可以预览和打开原回复或手动版本，再沿各自路径继续聊天。

编辑草稿按对话和消息分别保存，保留完整输入及打开时的历史版本。取消编辑会保存草稿；重新打开同一条消息会恢复，正常退出前会等待最新输入保存。清空的编辑草稿也会保留，直到输入有效文本或选择“放弃编辑草稿”。放弃会删除该消息的编辑草稿并重新载入当前消息，其他消息的编辑草稿和聊天输入保持可用。

重新生成保留原用户消息的 ID、时间、附件和手动编辑标记。被替换回复的编辑草稿随完整旧回复移入归档，仍可通过旧回复版本打开。草稿原本对应当前历史时，版本校验同步到内容相同的归档历史；已经冲突的草稿保留原校验值，继续提示冲突。备份验证也要求每个编辑草稿指向实际保存的消息，拒绝无法恢复到消息的孤立草稿。

如果对话在编辑过程中发生变化，保存或重发会拒绝覆盖并保留输入。重新打开旧草稿会显示冲突提示；可先复制需要的内容，再放弃旧草稿并编辑当前消息。保存成功只消耗对应编辑草稿；初始保存失败时，原对话、归档和编辑草稿均保持原状。普通发送也会在排队写入时重新核对历史，避免覆盖其他刚完成的编辑。

用户消息和编辑草稿的字符上限为 256000，助手正文和编辑草稿为 4000000；编辑草稿最多 100 个消息所有者，合计 JSON 的实际 UTF-8 字节上限为 32 MB。归档仍受 10000 条对话上限和现有聊天草稿 100 个所有者／32 MB 上限约束，助手回复组的编号上限仍为 10000。达到上限会明确拒绝保存，不自动淘汰其他内容。

编辑草稿保存失败时，窗口关闭和完整备份会拒绝继续，保留最新输入以便重试。删除对话会删除它的编辑草稿，针对已删除对话或消息的迟到保存会被拒绝。完整 JSON／gzip 备份保存手动编辑标记、原有生成证据、归档关系、回复版本以及每条消息的编辑草稿；旧工作台和旧备份没有编辑草稿字段时默认空列表。

七项聚焦原生检查，以及源码和实际打包 EXE 各 161 项完整回归中的七项消息编辑检查均已通过，使用真实模型 HTTP 验证仅保存不发送、原文／手动版本的独立上下文、取消和关闭前尚未完成防抖的输入、重新生成后的旧回复草稿恢复、冲突与放弃、真实保存失败、退出／备份保护、完整 gzip 恢复和对话删除。四张浅色、深色最小窗口、回复预览和错误状态截图已检查，760×540 窗口没有横向溢出，底部操作完整可见。

消息编辑沿用现有历史校验、原子保存、归档、草稿队列及退出保护。单元验证涵盖严格格式与字符／UTF-8 限额、独立所有者、完整上下文和生成证据、真实文件／重启／备份、失败回滚、串行冲突、普通发送保护及草稿队列中的新输入。突然断电、最大规模性能、完整无障碍和其他平台仍需单独验证。

完整单元测试共 445 项／46 个文件，核心行覆盖率 99.1%、分支 93.45%、函数 97.16%；类型检查、构建、产物与许可证核验通过。完整交付范围和剩余事项见 [DELIVERY.md](DELIVERY.md)。
