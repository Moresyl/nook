# 对话分支顺序

打开聊天顶部的“查看对话分支”，选择一条路径后，可使用“上移”“下移”调整同层顺序，也可“恢复时间顺序”。移动会带着整条子路径一起排列；各条对话仍保留自己的完整消息、模型设置、附件和草稿。浏览、排序和恢复顺序不会请求模型或切换当前聊天。

跨越每页 200 条的边界时，窗口会跟随所选分支翻页。搜索期间暂停排序，清空搜索后恢复；删除原对话后，仍可调整同一个原对话下幸存的分支。恢复只影响所选层，按创建时间和标识重新排序，不改变其他层、消息或聊天时间。异常循环关系仍按原有的时间规则展示，不因手动顺序改写原始关系。

普通聊天的顺序随本机历史、JSON／gzip 完整备份和应用重启保留。临时聊天的顺序随临时路径只保留在内存，不进入历史和完整备份。新增消息分支、重发分支和原文档案不继承父路径在另一层的序号。旧数据无需补写排序字段；排序仍遵守 10,000 条对话的现有限额。

排序通过后台的独立操作提交。保存失败保留当前顺序、选择和输入，可以直接重试。发送或重试的早期快照也会保留后台更新的顺序；旧客户端不能用整个聊天对象覆盖新排序。

分支增量的完整单元回归通过 564 项测试／56 个文件；加入七项独立启动检查后通过 571 项／57 个文件，核心行覆盖率仍为 99.13%。分支关系与排序服务的行、语句、函数和分支覆盖率均为 100%，包括实际磁盘失败、并发发送／重试、10,000 条边界、完整备份恢复和临时数据隔离。源码、应用包与实际安装版本都通过完整 188 项桌面回归和正常退出，其中九项分支检查覆盖真实跨分页排序、旧客户端保护、保存失败重试、完整备份恢复和重启。13 张源码截图与五张本次安装截图已分别逐张检查，三个排序按钮在深色最小窗口的 100%／125%／150% 缩放下可见并支持键盘操作。

四项设置、七项便携检查和两次长路径启动、实际安装／快捷方式／卸载保留数据均通过。九份真实记录通过同一应用字节的严格发布策略，见 [源码验收](../verification/branch-order-review-result.json) 和 [本地分发验收](../verification/branch-order-distribution-result.json)。远端验收仍在进行。已通过的旧应用记录保留其原有校验值，不能代替这次增量的发布验收；上一轮远端启动失败及新检查的实际覆盖范围见 [启动检查](CI-STARTUP.md)。
