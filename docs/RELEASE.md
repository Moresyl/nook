## 发布流程与约束

[Windows 工作流](../.github/workflows/windows.yml) 在分支提交、拉取请求和手动运行时验证代码；推送 `v<package.json 版本>` 标签时，验证成功后自动发布。目前实现 Windows x64 安装版和便携版。

验证依次执行固定版本依赖安装、类型检查、单元覆盖率、完整分发许可证检查、原始安装器输入校验、构建和 Windows 打包，再执行包审计、完整桌面和设置检查、启动器插件检查、两次便携启动退出，以及隔离中文路径中的实际安装、完整已安装桌面、快捷方式和卸载保留数据检查。已有安装、快捷方式或默认用户数据必须保留。静默安装检查与图形向导验收分别记录。

[发布准备脚本](../scripts/prepare-release.mjs) 要求标签、版本和构建提交一致，只允许生成的验证记录与提交内容不同。十份运行记录必须正常完成并匹配被审计的同一 EXE、ASAR 和各自包装文件；桌面至少 215 项、设置 4 项、便携 7 项及其两次启动。分支导航、临时聊天、模型比较等完整回归记录保留原请求数量、数据恢复和正常退出要求。缺失、失败或混用旧记录均由 [发布策略](../scripts/release-policy.mjs) 拒绝。源码 ZIP 来自同一提交，并包含原始开源许可证、法律文档和构建源码。

发布前核对上一版本、更新日志及本次提交。`CHANGELOG.md` 必须有唯一的版本日期小节，以及内容具体且有证据支持的“新功能”“变更与安全”“修复与完善”“安装”和 `English` 小节。首次独立版本不沿用原项目发布历史。

交付文件包含安装版、便携版、对应源码 ZIP、验证记录、中英文更新说明及 `SHA256SUMS.txt`。发布任务核对所有下载校验值，先建立草稿并上传完整文件，最后公开。失败草稿只允许同一提交重试，已公开或属于其他提交的版本不会被覆盖。构建任务仅有仓库读取权限，发布任务在全部验证成功后获得发布权限；GitHub Actions 固定到完整提交。
