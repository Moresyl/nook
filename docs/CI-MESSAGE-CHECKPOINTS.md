# 消息检查点原子合并

流水线 `37173408503` 在原来的四模型完成检查中失败：最后一次桥接读取耗时 9,422 ms，读取结果仍有一路运行中。两条成功 HTTP 流已在等待开始前发送完毕。现有证据不能区分队列等待、复制或 IPC 各自的耗时。

`MessageCheckpoints` 把同一事件循环轮次到达的回复保存合并为一个 `WorkspaceVault.update`，按对话和消息标识分别保存。在实际队列回调执行时复制最新回复；每个调用方等待整批提交后取得独立消息副本。新到达的检查点进入下一批。已删除的对话或消息不会重新创建，验证或写入失败时整批拒绝，后续有效批次可以重试。

回归使用真实工作台文件。旧实现对四个同时完成的回复执行四次完整更新，新实现执行一次，并保留完整上一份文件的原始字节。额外覆盖同一消息合并、Unicode 标识、排队后内容更新、写入中到达的新批次、写入失败、无效状态和已删除所有者。
