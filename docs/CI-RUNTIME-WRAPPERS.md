# 运行记录与分发启动器绑定

许可证资源更新没有改变应用主体，但重新生成了安装与便携启动器。实际安装在 192 项后失败后，旧安装记录仍保留其原范围；旧策略只比较应用主体，因此错误接受了旧安装启动器与新启动器组件审计的混合记录。这个缺口在 `verification/license-continuation-local-failure-result.json` 中保留，未作为分发验收。

当前策略要求安装结果的启动器 SHA-256 与实际安装启动器审计一致，便携运行结果也必须与实际便携启动器审计一致，并验证安装／卸载／便携启动器的哈希格式。原有 215 项门槛、正常关闭、许可证和其他运行条件保持原值。

新增两项回归在旧策略下失败；修改后 40 项测试及类型检查通过，发布策略的行、语句、函数、分支覆盖均为 100%。当前实际混合记录被新策略拒绝，此前已归档的完整十份记录仍按原应用体通过，未修改或重新标注时间。见 `verification/runtime-wrapper-proof-component-result.json`。

该修改保护证据校验，不修复比较续聊的持久状态耗时。当前安装和远端完整验收仍待该性能问题解决。
