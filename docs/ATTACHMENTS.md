# 文档与图片附件

图片预览中的“保存 JPEG”会保存导入后转换的 JPEG，默认沿用文件名并将扩展名改为 `.jpg`。可在主窗口和快速聊天使用；文件选择取消时不写入，写入失败后保留预览供重试。相同窗口中的保存请求互斥，导出进行中仍可查看其他图片；迟到结果只属于原来请求的图片。缩放比例不影响保存字节，导出不会修改附件、草稿或发送模型请求。原始 PNG、透明度、动画、元数据及导入前尺寸不会由此恢复；这不是原图导出。

新增验收覆盖真实磁盘字节、原生对话框边界、失败重试、延迟导出、快速聊天及六组明暗主题／缩放布局；系统保存对话框本身的物理交互仍需人工检查。当前构建与分发结果见[发布状态](RELEASE.md)。

快速聊天的最小窗口使用紧凑图片工具栏，保留图片区域。转换说明可用 Tab 聚焦，再用上下方向键滚动阅读；保存失败时完整提示与重试按钮保持可见。

最新图片交互增强通过类型、构建、139 文件／1637 项完整单元，以及两轮各 16 项原生附件检查。原生鼠标验证拖动启动阈值、启动后的连续跟随与松手停止，键盘验证 Home／End 首尾边界；最终四张明暗与 100／125／150% 原图逐张查看。图片就绪检查同时确认缩放按钮可用，保留草稿、附件与请求字节断言。[本轮证据](../verification/image-interaction-validation-review-result.json)。新应用体的完整桌面、打包与安装回归尚待完成。

聊天输入框支持文件选择、文件拖放和粘贴图片。点击附件可阅读 PDF 原件、查看提取文本或规范化后的图片；已发送消息和编辑消息窗口也可打开预览。导入时可以继续输入文字，发送和附件移除会暂时禁用。导入期间切换页面或恢复备份，会拒绝把迟到的结果放进另一份草稿，并提示重新导入。

图片查看器已支持大尺寸预览、同组图片前后切换、适应窗口、原始尺寸、缩放与拖动，加载失败后可以重试。键盘加减号缩放，`0` 适应窗口，`1` 原始尺寸，左右方向键切换，`Home`／`End` 跳到首张／末张，`Escape` 关闭并返回入口；按住 `Ctrl` 滚轮围绕指针缩放，双击在放大和适应窗口之间切换。拖动前过滤小于 4px 的微小移动，开始拖动后连续跟随，松开指针即停止。显示比例只改变查看效果，保存和发送的图片仍为下文定义的规范化内容。

此前查看器通过类型、构建及两轮各 16 组附件／图片桌面检查，均正常退出。该轮[浅色](images/image-viewer-light.png)、[深色](images/image-viewer-dark.png)、[125%](images/image-viewer-dark-125.png)及[150%](images/image-viewer-dark-150.png)截图已逐张核对。记录保留前置状态失败、退出超时、双击修正与截图帧同步过程；见[当时证据](../verification/image-viewer-review-result.json)。这些记录不代替新增拖动阈值和首尾导航验收。尚未进入分发版本；触屏双指缩放、旋转、翻转、原图导出及物理辅助技术验收仍未完成。

MCP 文件入口也复用该查看器。六组真实 MCP 文件专项通过，包含嵌套弹窗、三档缩放、键盘返回、原始字节导出、迟到结果隔离与重启；模型请求保持为零，最终正常退出 604ms。旧验证器引用已移除的通用弹窗页脚导致过一次失败，现改为核对实际缩放栏及全部按钮；未放宽尺寸、退出或数据断言。

| 输入 | 保存与发送的内容 |
| --- | --- |
| UTF-8 文本、代码、Markdown、CSV 等 | 原文本；UTF-16 需带大小端字节序标记 |
| PDF、DOCX、XLSX、PPTX、ODT、ODS、ODP、RTF | 本地提取的文字及文件名称、格式、原始大小；包含可读的表格、页或幻灯片内容 |
| PNG、JPEG、WebP、GIF | 本地转换的 JPEG，保留名称、源格式和原始大小；显示转换提示 |

图片会按方向信息旋转，最长边限制为 2,000 像素，透明区域使用白色背景，文件元数据会移除。动画仅保留第一帧，并明确提示。原始图片超过 4,000 万像素、解码失败或转换结果超过 2 MB 时，整个导入失败。持久化校验会核对 JPEG 实际头部尺寸与元数据，避免备份中的错误尺寸绕过限制。

每条消息最多 12 个附件，每个输入文件最多 12 MB，每批输入合计最多 24 MB。每个文字附件最多 256,000 字符；超限会报错，完整内容不会被悄悄截断。文档的解压内容、归档条目和解析资源有额外上限，每个文件在独立工作线程中解析，30 秒未完成即终止。损坏、加密、超限或解析库报告内容恢复不完整的文档会明确失败，批量导入不保留半批结果。没有可读文字的扫描 PDF 或纯图片文档需要 OCR 或单独的图片输入；当前未接入 OCR，也未开放旧版 DOC/XLS/PPT。

新导入的 PDF 在本机保留经过校验的原件，可阅读版式、选择文字、使用目录和全文查找、打开链接与只读批注，并保存完整原始文件。模型仍只接收提取文本；PDF 原件及其内嵌图片不会作为文件或图片自动发送。旧 PDF 附件没有原件时继续显示文本。Office 等其他文档目前保留提取文本，尚未提供其原始版式、表格编辑或幻灯片预览。见 [PDF 阅读](PDF-PREVIEW.md)。

资料库使用相同解析器导入文档，进行分块、关键词／语义检索；PDF 来源与已有引用也可打开保留的原件，见 [资料库文档](KNOWLEDGE.md)。

图片通过所选连接的原生内容格式发送：Responses 的 `input_image`、Chat Completions 的 `image_url`、Anthropic 的 base64 图片源，以及 Gemini GenerateContent 的 `inlineData`。Azure 使用所选 Responses/Chat 接口，Ollama 使用其 OpenAI 兼容接口。已有工具签名、推理项目及调用 ID 的续接行为沿用原协议。服务未明确提供的图片能力保持未设置；可在模型容量与能力中手动配置。明确设为不支持图片的模型会在创建请求前拒绝图片输入，保留草稿。未设置时允许发送，由实际服务确定支持范围，不从模型名称猜测能力。

后续请求会保留历史图片。整次请求最多 16 MB、最多 64 张历史图片；超过上限时提示减少文件或新建会话。此大小限制不是模型上下文 token 估算。已完成导入的附件随草稿、分支、重试和完整备份保存，正常退出和重启后可恢复。所有会话草稿仍共享 32 MB 保存额度；完整备份支持最多 256 MB 的 JSON 正文，压缩文件最多 64 MB，见 [备份文档](BACKUPS.md)。Markdown 对话导出只记录附件名称。

29 项附件测试覆盖八种文档格式、四种图片格式、两种 UTF-16 字节序、真实解码及元数据移除、首帧与缩放、损坏/加密/资源上限、无文字/超长/部分恢复、归档扩张、导入互斥、工作线程终止、协议内容和实际存储重启。独立 Electron 检查使用真实导入工作线程及隔离 HTTP 服务，验证八种连接方式中的图片字节与文档内容、预览、拖放/粘贴、模型拒绝、重启和备份。系统文件/备份对话框的返回边界使用测试进程夹具；联网模型识图质量、真实云端账号及原生系统选择器的人工交互仍待验证。

请求格式依据 [OpenAI 图片输入文档](https://developers.openai.com/api/docs/guides/images-vision)、[Anthropic Vision 文档](https://platform.claude.com/docs/en/build-with-claude/vision) 和 [Gemini GenerateContent 内容定义](https://ai.google.dev/api/generate-content)。本地解析配置依据 [officeParser 官方文档](https://github.com/harshankur/officeParser)。
