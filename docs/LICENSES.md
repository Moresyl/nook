# License and artifact verification

The upstream LGPL v3 document is retained byte for byte in `LICENSE`; its SHA-256 is `e3a994d82e644b03a792a930f574002658412f62407f5fee083f2555c5f23118`. The upstream Cargo workspace declares LGPL-3.0-or-later, which is retained as this project's package license. `COPYING` contains the corresponding GNU GPL v3 document from the GNU website. `licenses/project/NOTICE.txt` records the upstream revision and independent implementation. Legal names and copyright statements are preserved; the product identity scan does not delete them.

`pnpm notices` reads the installed production dependency graph through pnpm and retains full license/notice/COPYING/copyright documents, including nested notices. Exact package identity is checked against installed metadata. Duplicate installations are deduplicated only when their legal documents agree; missing/empty documents, conflicting copies and escaping dependency roots fail generation. `licenses/dependencies.json` records versions, declared licenses, document paths, byte counts and SHA-256 hashes without local absolute paths. The graph includes renderer packages and transitive peers; it does not claim every graph entry ships as a separate module. Original legal documents are preserved byte for byte in `licenses/runtime`, with a readable combined `THIRD_PARTY_NOTICES.txt`. Git attributes disable newline conversion for all retained legal files; real Git tests verify original CRLF bytes with both core.autocrlf=true and input.

The bundled-asset inventory separately records supplied Carlito fonts and their complete OFL v1.1 notice, the unchanged Inter 4.1 variable font and complete original OFL notice, project license documents and four ConPTY binaries distributed by node-pty 1.1.0. The original node-pty license and those four binaries match the official v1.1.0 Git blobs. The asset inventory records their original package's MIT declaration/license without changing the vendor copyright. Dependency upgrades require updating asset provenance and hashes deliberately.

The math font asset group retains all 59 supplied external KaTeX fonts and the complete Size3 WOFF2 font recovered from the supplied app-shared stylesheet as a local file. All 60 files match KaTeX 0.16.45 and retain their original names and bytes. Their embedded nameID 13 declarations explicitly license the fonts under OFL 1.1; the original copyright/RFN notices for all 12 families and the full official OFL document are retained. The library/rendering styles retain their separate complete MIT document. Package-level MIT metadata alone would misclassify the font license. The stylesheet hash pins the supplied rendering rules and complete faces; package verification checks renderer/module font hashes and unchanged legal files. See [RICH-CONTENT.md](RICH-CONTENT.md) and the [official upstream clarification](https://github.com/KaTeX/KaTeX/issues/339).

The published rehype-katex 7.0.1 and remark-math 6.0.0 packages omit a root license document. Their original monorepo license was retrieved from each package's exact npm gitHead revision and checked against the official Git blob. `licenses/supplements.json` records immutable source URLs, original SHA-256 and pinned package integrity. Generation verifies those package integrities against pnpm-lock.yaml and accepts a supplement only for the exact name/version, declaration and document hash. A changed document, unpinned source, version mismatch or escaping path fails. Installed original notices always take precedence; identical original/supplemented copies deduplicate without losing provenance. No generic license template replaces a missing original.

`pnpm notices:check` verifies the current dependency graph, retained documents and asset hashes. Packaging regenerates notices before building and places the legal files in the resources directory. `pnpm test:package` inspects the ASAR's application files and executable metadata, checks that compiled assets match the previously verified build, detects the previous project identity in product paths/text, and verifies packaged legal documents against their original hashes. Electron's `LICENSE.electron.txt` and `LICENSES.chromium.html` are verified against the installed Electron distribution. Vendor legal files are retained unchanged.

Windows distribution records separately retain NSIS core/template notices, StdUtils, UAC, nsis7z and the historical elevation helper. `licenses/distribution.json` pins electron-builder 26.15.3, its legacy NSIS toolset (`0.0.0`), 28 compiler/stub/plugin/helper input hashes, original complete documents and source/release archives. `pnpm prepare:installer` checks the configured toolset, installed builder version and resolved bytes before `package:win`; a changed dependency, environment override or file fails. Eight original installer templates and the original portable launcher are pinned separately in `identity/windows/templates.json`. Preparation preserves the flat installer templates while replacing their audited shell calls. The per-build Windows factory checks the original portable template and changes its output/cleanup paths; native NSIS file extraction retains long-path files. The original MIT template license is retained, and modified scripts identify their origin. The current bootstrap separately verifies six installer, five uninstaller and two portable plugins, and each application-directory audit verifies all 261 unpacked file integrity hashes. The distribution collector checks legal/source hashes, directory boundaries and explicit unresolved declarations. Combined notices contain readable original documents and source-file references; original archives remain byte for byte separate files.

The shipped legacy elevation helper identifies Johannes Passing and version 1.0.0.2894. Its [original source header](https://github.com/jpassing/elevate/blob/d5cfc93d1ce06844a39d1a334a7a8081d26b6204/Elevate/main.c) explicitly declares LGPL 2.1 or later; the repository's generic MIT template has placeholder copyright holders. UAC retains its original zlib/libpng notice and source release.

The former WinShell plugin's [official release](https://nsis.sourceforge.io/WinShell_plug-in) supplies only DLLs and an incomplete Freeware declaration. It has been removed from the product and replaced with project-owned NSIS macros calling the original open source System plugin and documented Windows COM APIs. Shortcut AppUserModelID writing, pinned-item removal and application-destination cleanup retain their original responsibilities. Empty, spaced and oversized IDs are rejected before writes or cleanup. Original research material remains outside the product; its three former distribution files and input record are excluded. Earlier private Git history still requires publication review. No binary redistribution permission is inferred from the wiki label.

`pnpm test:shell` compiles and executes the actual x86 NSIS/System macros in an isolated Unicode/space directory, checks invalid inputs, register/stack preservation and unchanged corrupt files, and independently reads the resulting shortcut properties through Electron. Five checks passed. An optional `QIYAO_INSTALLED_SHORTCUTS` JSON array together with `QIYAO_AUDIT_DIRECTORY` additionally verifies both real installer-owned links: exact application ID, target, arguments, working directory, description and icon. Both current links passed. The metadata reader is a headless batch utility that exits explicitly after synchronous report writes; it does not change the application's normal quit path. Two earlier reader failures are retained, including diagnostics showing all four reads/report writes completed before its thirty-second exit deadline. Physical pinned-item interaction remains separate.

`pnpm test:distribution` uses a full 7-Zip executable specified by `QIYAO_ARCHIVE_TOOL`, with NSIS support, to inspect the actual installer, its embedded uninstaller and portable wrapper. The rebuilt executables verify six, five and three embedded plugins respectively against original hashes; missing or changed declarations fail, and WinShell is explicitly rejected. None embeds nsProcess. Unused plugin research material is kept outside the product. Package verification rejects undeclared leftover files in the distribution directory. The archive tool's hash is recorded for reproducibility; the verification tool is not shipped with the application.

Package verification checks the exact distribution manifest, all its legal/source-file hashes and, when present, the actual shipped `resources/elevate.exe`. `pnpm test:package -- --installer` requires the helper instead of allowing its absence in a directory-only build. Setting `QIYAO_AUDIT_DIRECTORY` to an actual installed application directory applies the same product/legal checks and writes a separate installed audit result. Input hashes and legal retention do not substitute for real install/uninstall, portable-wrapper, update or platform checks.

An actual installation exposed an archive compatibility defect: automatic ARM64 filtering retained the original files in the archive, but the pinned nsis7z/LZMA SDK 19 decoder omitted ARM64 executable/DLL helpers during extraction. `package:win` now uses the project-owned builder entry point with the inventory's explicit BCJ filter. The corrected actual installation passed the complete native-asset and original legal/source hash checks. No native asset is removed or exempted to pass this check. `pnpm test:portable` separately starts the real portable wrapper from an isolated Chinese/space path, audits its actual extracted application and exercises native PTY, persistence, normal exit and extraction cleanup.
